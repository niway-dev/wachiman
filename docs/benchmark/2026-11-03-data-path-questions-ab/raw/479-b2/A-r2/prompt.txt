An entry has: the `action` and its `location` (path:line), the `equivalent_path`, `before_after`,

repository-relative, for every claim in the entry), and a `status`. It is "closed" only when you

Every finding has a severity, which tells the author when to act, and a topic, which says
what it is about. Pick the severity by its test, not by how serious the finding feels:
- "blocker": fix before merging. Only when you can name the input, state or trust boundary that
  fails if the change merges as is.
- "fix": wrong today; fix it in this pull request, but it does not block the merge. The fix is
  specific and the author would not argue with it.
- "consider": would be better, and the author may decline. A matter of judgement, not a defect.
- "info": nothing to change, awareness only. It asks for no reply and is never posted on a line.
Two tests settle a severity that feels uncertain, and they come first:

- If a user can lose data or see a wrong result silently (no error, log or visible state tells

Confidence is separate from severity. Severity says how bad the finding is if it is true;
confidence says how sure you are that it is true, given what you read:
- "high": you read the lines that establish every premise, and the failure follows from them.
- "medium": the argument holds, but one premise rests on code you did not read or a condition you

- "low": plausible, not established.
A finding with confidence "low" at severity "fix" or above is posted with topic "question",
worded as a question to the author, never as a fact.
Topics:

# Development Rules

## Brand Identity

Before changing Kaipu's name, story, logo, mascot, onboarding, or marketing copy, read
`apps/documentation/src/content/docs/marketing/brand-identity.md` — the canonical

## Template Customization

This is a multi-pattern template. Before starting development, customize it:

- `bun run customize` — Interactive CLI: choose pattern, optional features, project name. Handles directory deletion, package.json cleanup, CI/CD generation, infra-env cleanup, lint config cleanup, and scope rename. Self-deletes after completion.
- `bun run rename <scope>` — Standalone scope rename (`@kaipu` -> `@your-scope` across 60+ files). Use if you only need to rename.

Always recommend `bun run customize` on a fresh clone. Do NOT do manual file-by-file customization.

## Development Workflow: MVP First, Then Refactor

When building new features, follow a two-phase approach:

### Phase 1: MVP (Speed)

Build the feature the simplest way possible. All logic can live inline in the frontend and backend:

- Add routes with inline business logic directly in `apps/server/src/routes/`
- Add serverFn with inline logic in `apps/web/src/functions/`
- Use `@kaipu/infra-db` repositories directly from route handlers
- Focus on making it work end-to-end (UI -> API -> DB)
- No need for use cases, domain interfaces, or mappers at this stage

### Phase 2: Refactor to Architecture Standards

Once the feature works, refactor to follow the layer architecture:

1. **Domain** (`packages/domain/`) -- Extract interfaces, schemas, types, constants
2. **Application** (`packages/application/`) -- Extract use cases that depend only on domain interfaces
3. **Infrastructure** (`packages/infra-db/`, `packages/infra-auth/`) -- Repository implementations, mappers
4. **Consumers** (`apps/*`) -- Thin handlers that wire application use cases with infra implementations

The dependency rule is strict: domain <- application <- infra, and only apps wire them together.

### When to Refactor

- When a second consumer needs the same logic (e.g., both web serverFn and API route)
- When business logic exceeds ~15 lines in a route handler
- When the feature is stable and tested

## Architecture

This project uses DDD + Hexagonal Architecture with layer-first package structure:

```
packages/domain/        Pure. Mobile-safe. Constants, schemas, types, interfaces.
packages/application/   Use cases. Server-only. Depends on domain interfaces.
packages/infra-db/      Infrastructure. Server-only. Drizzle repos, mappers, schemas.
```

Infrastructure packages use the `infra-*` naming convention to make architectural intent explicit.

## Skill Configuration

Skills in `.claude/skills/` may have a **Configuration** table with paths (e.g., `DOCS_BASE`). If you detect a mismatch between a skill's configured path and the actual project path, update the skill's Configuration table directly so future sessions use the correct path without re-discovering it.

## Client-Server Architecture (Web + Elysia API)

The web app (TanStack Start) proxies all API requests through itself to the Elysia backend. This solves cookie-based auth on Cloudflare Workers where cross-origin cookies don't work.

**How it works:**

- Browser talks only to the web Worker domain (same-origin)
- Web Worker proxies `/api/auth/*` and `/api/v1/*` to the Elysia API Worker
- In production: Cloudflare Service Bindings (direct Worker-to-Worker, no public DNS)
- In local dev: regular `fetch()` fallback (Service Bindings not available)
- Set-Cookie headers are rewritten to strip `domain=` so cookies are assigned to the web domain

**Key files:**

- `apps/web/src/lib/api-fetch.ts` — Service Binding fetch wrapper with local dev fallback
- `apps/web/src/routes/api/auth/$.ts` — Auth proxy (forwards x-forwarded-host/proto)
- `apps/web/src/routes/api/v1/$.ts` — API proxy
- `apps/web/wrangler.jsonc` — Service Binding declared in `services` array
- `apps/web/src/lib/client-treaty.ts` — Eden Treaty uses `window.location.origin` (not server URL)

**Important:**

- Web app does NOT run Better Auth locally — it proxies to the backend's auth
- `@kaipu/infra-auth` is NOT a dependency of the web app
- CORS on the server is only for mobile (exp://, mobile://) — web is same-origin via proxy
- After modifying wrangler.jsonc, run `wrangler types` to regenerate `worker-configuration.d.ts`

## Package Import Rules

- `domain` never imports from `application` or `infra-*`
- `application` never imports from `infra-*` (uses domain interfaces)
- `infra-*` never imports from `application`
- Mobile app (`apps/mobile/`) only imports from `@kaipu/domain`

## Secrets: Infisical

All environment values come from Infisical. There are no hand-maintained `.env`
files — where one exists it is **generated** and gitignored, never edited.

First-time setup (once per machine):

```bash
bun run setup      # reports which global tools you are missing, and how to get them
infisical login
```

`scripts/setup-dev.sh` **checks, it never installs** — it reports what is missing
and the command to install it, so nothing lands on your machine that you did not
run yourself. See the
[tool-doctor pattern](https://github.com/csdev19/general-knowledge/blob/main/conventions/tool-doctor-pattern.md).

If Homebrew refuses with "Xcode is too outdated", this points it at the Command
Line Tools and fixes it for every formula:

```bash
sudo xcode-select --switch /Library/Developer/CommandLineTools
```

Do not install the CLI with `bun add` — bun blocks the `preinstall` that
extracts the binary, so you get the package without a working command.

Then generate the local files, from the repo root:

```bash
bun env:pull       # scripts/env-pull.sh: every app's .env, plus packages/infra-db/.env
```

That is the only command that talks to Infisical in local development:

- `bun run dev` reads each app's `.env` and never calls Infisical, so an
  Infisical outage cannot block it.
- `bun run db:*`, `plan` and `test:integration` load `packages/infra-db/.env`
  with `bun --env-file`. A variable set inline in the shell wins over the file.
- A missing file fails fast through `scripts/require-env.sh`, and the Zod
  schemas validate through `parseEnv` (`@kaipu/infra-env`); both point to
  `bun env:pull`.
- The pull is all or nothing: a failed fetch leaves every existing `.env` as it
  was.

Changing a value means changing it in Infisical, then `bun env:pull` and a
restart. Never hand-edit a generated `.env`.

Layout: environment slug `dev` (the UI shows it as "Development"). Secrets live
in six folders — `/public`, `/database`, `/cloudflare`, `/auth`, `/email`,
`/signing` — and tags name the consumer. `infisical export` has no
`--recursive`, so `env-pull.sh` lists the folders explicitly; a new folder must
be added there.

`scripts/with-env.sh` (live `infisical run`) remains only for the signed
production build in `apps/kaipu-record/scripts/build-mac-local.sh`. CI never
needs a secrets CLI: workflows inject their own values, and `require-env.sh`
passes straight through when `CI` is set.

## Native dependencies: no install scripts

There is **no `postinstall`** in this repo, and none should be added. `bun install`
is not allowed to compile code, download binaries, or run anything you have not
read — the same rule as `scripts/setup-dev.sh`, which checks and never installs.
The reusable form of this, including why it breaks unrelated CI jobs, is the
[native dependencies pattern](https://github.com/csdev19/general-knowledge/blob/main/desktop/native-dependencies.md).

The desktop app has one native dependency, `uiohook-napi` (the global mouse hook
behind auto-zoom on clicks). It is **patched**: `patches/uiohook-napi@<version>.patch`
(declared in the root `package.json` under `patchedDependencies`) carries the
upstream fix for a startup deadlock in `uIOhook.start()` that froze the whole app
at "start recording" ([SnosMe/uiohook-napi#66](https://github.com/SnosMe/uiohook-napi/pull/66),
unmerged as of 2026-10-28). `bun install` applies the patch to the C **sources**
only; the shipped prebuilt binary stays unpatched, and `electron-builder.yml` sets
`npmRebuild: false`, so the fix exists at runtime only after an explicit rebuild:

```bash
bun run rebuild:native   # compiles the patched sources against the installed Electron
```

`bun run setup` reports when that rebuild is pending and prints this command —
it compares a stamp in `node_modules` against the installed Electron version plus
a hash of `patches/*.patch` (`scripts/native-deps-stamp.sh`), so a fresh install,
an Electron bump or a changed patch all show up. Every packaging path
(`build:mac`, `build:unpack`, `build:win`, `build:linux`, `release-desktop.yml`)
calls it explicitly, because a release must not depend on someone remembering.

If you skip it the app still runs, and that is the trap: the Node prebuild is a
N-API module, so Electron loads it without complaint — you get the **unpatched**
hook with the deadlock, and nothing in the UI tells you. (The earlier belief that
a skipped rebuild degrades to "no clicks" was wrong; a hung main process on
2026-10-28 was running the prebuild.) `click-hook.ts` still degrades to "no clicks"
when the module is missing or fails to load. Bumping `uiohook-napi` means
re-checking whether the fix landed upstream and re-creating the patch
(`bun patch uiohook-napi`); `click-hook-native-patch.test.ts` fails until you do.

  371 +      const copied = await copyExclusive(media, staged);
  372 +      if (copied === "taken") throw new Error(`staging path taken: ${staged}`);
  373 +      await after("media-copied");
  374 +      if ((await fs.sha256(staged)) !== journal.media.sha256) {
  375 +        await rollBackTarget(to, newId, assetId, staging, null);
  376 +        await rm(journalPath(deps.journalDir, journal.moveId), { force: true });
  377 +        return refuse("checksum-mismatch");
  378 +      }
  379 +      await after("media-verified");
  380 +      const placed = await placeNoReplace(staged, finalMedia(newId), { stuck: "rollback" });
  381 +      if (placed === "taken") throw new Error(`target media taken: ${finalMedia(newId)}`);
  382 +    }
  383 +    mediaPlaced = true;
  384 +    await after("media-placed");
  385 +
  386 +    // Freshness caches follow the new file (decision 8). Best effort: a cache, not the item.
  387 +    await refreshFreshness(to, newId, journal).catch((error: unknown) =>
  388 +      console.error("move: could not refresh the moved item's caches", error),
  389 +    );
  390 +
  391 +    // ── 6. Committed: the source goes.
  392 +    journal.phase = "committed";
  393 +    await writeJournal(deps.journalDir, journal);
  394 +    await after("committed");
  395 +    await rm(media, { force: true });
  396 +    await after("source-media-deleted");
  397 +    await removeCompanions(from.companionPaths(id));
  398 +    await after("source-companions-deleted");
  399 +
  400 +    // ── 7. Done.
  401 +    await rm(stagingDir(target.directory, journal.moveId), { recursive: true, force: true });
  402 +    await rm(journalPath(deps.journalDir, journal.moveId), { force: true });
  403 +    return { ok: true, id, newId, mode };
  404 +  } catch (error) {
  405 +    if (error instanceof SimulatedCrash) throw error;
  406 +    if (mediaPlaced) {
  407 +      // Past the commit: the target holds the item. Healing finishes the source side.
  408 +      console.error(`move of "${id}" failed after its commit; healing finishes it`, error);
  409 +      await healEntry(journal, {
  410 +        journalDir: deps.journalDir,
  411 +        fs,
  412 +        resolve: async (w) => w.directory,
  413 +      });
  414 +      return { ok: true, id, newId: journal.targetId!, mode: "copied" };
  415 +    }
  416 +    if (journal.targetId) {
  417 +      await rollBackTarget(
  418 +        to,
  419 +        journal.targetId,
  420 +        assetId,
  421 +        stagingDir(target.directory, journal.moveId),
  422 +        null,
  423 +      );
  424 +    }
  425 +    await rm(journalPath(deps.journalDir, journal.moveId), { force: true });
  426 +    throw error;
  427 +  }

  464 +/**
  465 + * Put `from` at `to`, never replacing a file there: a hard link on the same volume, else an
  466 + * exclusive copy (verified by sha256 when asked, by size otherwise).
  467 + */
  468 +async function transfer(
  469 +  from: string,
  470 +  to: string,
  471 +  options: { sameDevice: boolean; verify: boolean; fs: MoverFs },
  472 +): Promise<void> {
  473 +  if (options.sameDevice) {
  474 +    try {
  475 +      await options.fs.link(from, to);
  476 +      return;
  477 +    } catch (error) {
  478 +      if (!NO_HARD_LINK.has(codeOf(error) ?? "")) throw error;
  479 +    }
  480 +  }
  481 +  if (!options.verify) {
  482 +    await copyFile(from, to, constants.COPYFILE_EXCL);
  483 +    const [a, b] = await Promise.all([stat(from), stat(to)]);
  484 +    if (a.size !== b.size) throw Object.assign(new Error(`short copy: ${to}`), { code: "EIO" });
  485 +    return;
  486 +  }
  487 +  const copied = await copyExclusive(from, to);
  488 +  if (copied === "taken") throw Object.assign(new Error(`"${to}" exists`), { code: "EEXIST" });
  489 +  if ((await options.fs.sha256(from)) !== (await options.fs.sha256(to))) {
  490 +    await rm(to, { force: true });
  491 +    throw Object.assign(new Error(`checksum mismatch: ${to}`), { code: "EIO" });
  492 +  }
  493 +}

  564 +export interface HealReport {
  565 +  /** Entries finished: rolled forward or back. */
  566 +  healed: number;
  567 +  /** Entries waiting for an unavailable workspace. */
  568 +  waiting: number;
  569 +  /** Entries kept and surfaced: neither side could be proven complete. */
  570 +  quarantined: MoveJournal[];

  573 +/**
  574 + * Finish every journal entry from what is on disk (ADR 0033, decision 6). Runs at startup and
  575 + * before each move. One rule covers every case: a side is deleted only when the other side is
  576 + * verified complete, and a phase of `copying` never justifies deleting a target.
  577 + */
  578 +export async function healMoves(deps: HealDeps): Promise<HealReport> {
  579 +  const fs: MoverFs = { ...defaultFs, ...deps.fs };
  580 +  const report: HealReport = { healed: 0, waiting: 0, quarantined: [] };
  581 +  let names: string[];
  582 +  try {
  583 +    names = await readdir(deps.journalDir);
  584 +  } catch {
  585 +    return report;
  586 +  }
  587 +  for (const name of names.filter((n) => n.endsWith(".json"))) {
  588 +    let journal: MoveJournal;
  589 +    try {
  590 +      journal = JSON.parse(await readFile(join(deps.journalDir, name), "utf-8")) as MoveJournal;
  591 +    } catch (error) {
  592 +      console.error(`move journal ${name} cannot be read; kept`, error);
  593 +      continue;
  594 +    }
  595 +    if (journal.quarantined) {
  596 +      report.quarantined.push(journal);
  597 +      continue;
  598 +    }
  599 +    const outcome = await withItemLock(journal.source.workspaceId, journal.sourceId, () =>
  600 +      healEntry(journal, { ...deps, fs }),
  601 +    ).catch((error: unknown) => {
  602 +      console.error(`healing move ${journal.moveId} failed; it is retried later`, error);
  603 +      return "waiting" as const;
  604 +    });
  605 +    if (outcome === "healed") report.healed += 1;
  606 +    else if (outcome === "waiting") report.waiting += 1;
  607 +    else report.quarantined.push(outcome);
  608 +  }
  609 +  return report;
  610 +}

  612 +async function healEntry(
  613 +  journal: MoveJournal,
  614 +  deps: { journalDir: string; resolve(side: MoveSide): Promise<string | null>; fs: MoverFs },
  615 +): Promise<"healed" | "waiting" | MoveJournal> {
  616 +  const sourceDir = await deps.resolve(journal.source);
  617 +  const targetDir = await deps.resolve(journal.target);
  618 +  // A workspace that is not connected waits: its side cannot be inspected.
  619 +  if (sourceDir === null || targetDir === null) return "waiting";
  620 +  const from = new LibraryVault(sourceDir);
  621 +  const to = new LibraryVault(targetDir);
  622 +  const staging = stagingDir(targetDir, journal.moveId);
  623 +  const done = async (): Promise<"healed"> => {
  624 +    await rm(staging, { recursive: true, force: true }).catch(() => {});
  625 +    await rm(journalPath(deps.journalDir, journal.moveId), { force: true });
  626 +    return "healed";
  627 +  };
  628 +  const quarantine = async (reason: string): Promise<MoveJournal> => {
  629 +    const kept = { ...journal, quarantined: reason };
  630 +    await writeJournal(deps.journalDir, kept);
  631 +    console.error(`move ${journal.moveId} of "${journal.sourceId}" kept for review: ${reason}`);
  632 +    return kept;
  633 +  };
  634 +
  635 +  const sourceMedia = join(sourceDir, `${journal.sourceId}${journal.ext}`);
  636 +  const sourceStat = await statOrNull(sourceMedia);
  637 +  const sourcePresent = sourceStat !== null;
  638 +  const sourceMatches =
  639 +    sourceStat !== null &&
  640 +    sourceStat.size === journal.media.size &&
  641 +    sourceStat.mtimeMs === journal.media.mtimeMs;
  642 +
  643 +  if (journal.targetId === null) {
  644 +    // Died before the stem was reserved, or in the middle of it: only a record can be there.
  645 +    if (sourcePresent) {
  646 +      await removeOrphanRecords(to, journal.assetId);
  647 +      return done();
  648 +    }
  649 +    return quarantine("source media missing before the target was reserved");
  650 +  }
  651 +
  652 +  const targetId = journal.targetId;
  653 +  const targetMedia = join(targetDir, `${targetId}${journal.ext}`);
  654 +  const targetMatches = await mediaMatches(targetMedia, journal, deps.fs);
  655 +  const targetPresent = (await statOrNull(targetMedia)) !== null;
  656 +  const targetRecord = await readSidecarStrict(to.sidecarPath(targetId));
  657 +  const recordIsOurs =
  658 +    targetRecord.status === "missing" ||
  659 +    (targetRecord.status === "ok" && targetRecord.sidecar.assetId === journal.assetId);
  660 +
  661 +  if (targetPresent && targetMatches && recordIsOurs) {
  662 +    // Committed, whatever the phase says: roll forward.
  663 +    if (targetRecord.status === "missing") {
  664 +      const read = await readSidecarStrict(from.sidecarPath(journal.sourceId));
  665 +      if (read.status !== "ok")
  666 +        return quarantine("target record missing and source record unreadable");
  667 +      await atomicWriteFile(to.sidecarPath(targetId), JSON.stringify(read.sidecar, null, 2));
  668 +    }
  669 +    if (journal.phase !== "committed") {
  670 +      await writeJournal(deps.journalDir, { ...journal, phase: "committed" });
  671 +    }
  672 +    await refreshFreshness(to, targetId, journal).catch(() => {});
  673 +    // A drag copy of the item could still name its bytes in the source (decision 11).
  674 +    await rm(join(sourceDir, META_DIR, "drag"), { recursive: true, force: true }).catch(() => {});
  675 +    if (sourcePresent) await unlink(sourceMedia).catch(() => {});
  676 +    await removeCompanions(from.companionPaths(journal.sourceId));
  677 +    return done();
  678 +  }
  679 +
  680 +  if (sourcePresent && !targetPresent) {
  681 +    // Not committed: undo the target side. The source was never touched.
  682 +    const placedStaged = join(staging, `${targetId}${journal.ext}`);
  683 +    await rm(placedStaged, { force: true }).catch(() => {});
  684 +    await rollBackTarget(to, targetId, journal.assetId, staging, null);
  685 +    return done();
  686 +  }
  687 +
  688 +  if (sourcePresent && targetPresent) {
  689 +    // A partial or foreign target file.
  690 +    if (sourceMatches && recordIsOurs) {
  691 +      await rollBackTarget(to, targetId, journal.assetId, staging, targetMedia);
  692 +      return done();
  693 +    }
  694 +    return quarantine("both media files present and neither proven complete");
  695 +  }
  696 +
  697 +  if (!sourcePresent && targetPresent) {
  698 +    return quarantine("source gone and the target media does not match: the only copy");
  699 +  }
  700 +
  701 +  // Neither side has the media: a verified copy may still be in staging.
  702 +  const staged = join(staging, `${targetId}${journal.ext}`);
  703 +  if (recordIsOurs && (await mediaMatches(staged, journal, deps.fs))) {
  704 +    if ((await placeNoReplace(staged, targetMedia, { stuck: "rollback" })) === "placed") {
  705 +      return healEntry(journal, deps);
  706 +    }
  707 +  }
  708 +  return quarantine("no media on either side");
  709 +}

  711 +/** The file at `path` is the journal's media: same size, and the same mtime or sha256. */
  712 +async function mediaMatches(path: string, journal: MoveJournal, fs: MoverFs): Promise<boolean> {

  716 +  if (!journal.media.sha256) return false;
  717 +  try {
  718 +    return (await fs.sha256(path)) === journal.media.sha256;
  719 +  } catch {
  720 +    return false;
  721 +  }
  722 +}
