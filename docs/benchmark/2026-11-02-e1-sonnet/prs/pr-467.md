## Notes

- Precision held on Sonnet: no invalid finding in 36 postings. The only unconfirmed item is the picker-clipping question (N2), also unconfirmed in Opus. Four are partly valid (A3 x2, A5, N3 variant). Volume is higher (15/13/8 vs 9-10), mostly from cleanup, test and duplicate items.
- Recall on the expected set is level with Opus (mean 3.7 each). Sonnet gains E10 (2/3 vs 1/3) and A5/A3 partly; it loses E3 (0 vs 1) and E6 (1 partial vs 1 full + 1 partial). E2, E4, E5 stay 0/3 for both.
- Sonnet found one Medium that Opus never did: NS1 (Fill/Fit reuse), in 2 of 3 runs. It is a real defect but was already present in the Prepare page, so it is not a regression of this PR.
- Medium+ coverage is lower than Opus on the items that need the Recent exports list: A2 0/3 (Opus 1/3) and E1 only half in one run. The A2 misses are all cause (2): the filter code was cited as evidence, but no contract asked what an editor export looks like in the list.
- E1 shows the contract failure modes clearly: S8 and S9 hedged the missing re-list in a contract or summary and posted nothing; S7 read the same code and closed the question the wrong way ("A finished copy appears when `onLibraryChanged` triggers a refresh").
- E4 was seen in all three Sonnet runs' contracts ("Focus is not moved into or back out of the dialog") and deliberately not reported ("I am not reporting it as a defect", S9). Same pattern as Opus's E10 in W4: seen, judged minor, not posted.
- Sonnet runs cost $2.09, $1.78 and $1.60 and used 6 batches each (Opus cost is not in the files I read). S9, the cheapest, posted 8 findings, all Valid and with the highest message score, but found the fewest expected items (3).
- Verification limits: A1 and N2 depend on Electron and layout behaviour that no run and I did not execute; NS2 is a read of the focus and event path, not a run. Everything is "Valid by reading".
