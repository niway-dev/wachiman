### Opus found, Sonnet lost: cause per Sonnet run

**E1 (lost in S7 and S8). Cause 3 in both: a contract stated the defect, no finding posted.**

- **S7**
  - Contract on the card window root: "If the renderer never loads, nothing shows and there is no fallback (documented under "Not done")."
  - The contract on the `show` flow also starts "A window that is created but never loa…" (text cut off).
  - The summary does not mention it.
  - Likely reason: the PR's backlog doc lists exactly this under "Not done" (floating-ready-window.md:55-56), so S7 treated it as a known, accepted limitation. That reading is half right: the doc names the missing fallback, but not that `show()` already answered true.
- **S8**
  - Contract on `recording-ready:show`: "A window that is created but never loads its renderer never reports ready, so nothing shows and there is no…" (cut off).
  - Contract on the detail page: "Main has answered true, so there is no fall…".
  - Batch 2 summary: "I found no blocker or fix-level defect in this part."
  - Same pattern as S7: stated in a contract, not posted.
- **S9 found it**: `Consider · bug` at recording-ready-window.ts:134. Its closed contract says "Load fails after the window object exists: true is returned but nothing is ever shown, silently". That contract became a finding.

**NF2 (lost in S7, S8 and S9). Cause 1 in all three: the cited evidence lacked it.**

- None of the contracts cite `area-geometry.ts` (`fullDisplayBorderAllowed`, lines 81-92), `recording-hub.ts:701-703` (the hub's use of it) or `capture-toast-window.ts:305-307` (the toast's "second guard" comment). Those are what establish that content protection paints black before Windows build 19041.
- **S7** cites `recording-hub.ts:689` (hides the main window) and `index.ts:449-457` only. Contract text: "The card is not hidden when a new take starts, so a press during the take shows the main window mid-recording (reported as a finding)." It never considers the card itself being recorded.
- **S8** is the nearest miss. It cites `capture-window-hooks.ts:52-58` (`dismissToast` in `beforeCapture`) and writes "The card is content-protected, but the main window is not". It assumes content protection always works, so it never asks what happens on old Windows. Its Fix ("call `recordingReady?.close()` when a take starts") would also remove NF2, but the effect is never described.
- **S9** cites `recording-hub.ts:689` and writes "Content protection keeps the card out of the video, but not the main window."
- No contract in any Sonnet run describes the card landing in the next recording. Cause 4 (no contract, no finding) is the honest fallback for S7 and S9 if the call-site list did hold `area-geometry.ts`, which I cannot see.

## Notes

- Sonnet matches Opus on the hardest issue: E3 (difficulty 5) 3/3, all `Consider · bug`, one clean comment each, no duplicates.
- Sonnet is better on NF1 (3/3 vs 1/3) and on E2 (2/3 vs 0/3). Opus's summaries all said the sender checks existed for "each message"; S9 repeats that mistake ("the sender checks are in place"), S7 and S8 do not.
- Sonnet is worse on NF2 (0/3 vs 2/3) and E1 (1/3 vs 2/3). NF2 failed for lack of evidence (nobody cited `fullDisplayBorderAllowed`); E1 failed after the contract had stated it.
- The E1 misses (S7, S8) coincide with the PR's own "Not done" note admitting the missing fallback. Opus W4 and W6 posted E1 anyway. A rule like "a documented limitation still needs a finding when the code answers true first" would address the S7/S8 loss.
- Contract-versus-finding gap: in S7, S8 and S9 a contract described a defect that was not posted (E1 in S7/S8); Opus had the same in W5 (E1). This is the clearest repeating pattern across both models.
- S8 spent 4 of its 7 comments on test and docs hygiene (all valid, all Low) and none on E1; S9 posted only 3 findings but all three were real Medium bugs.
- E4 is 0/6 across both models and S7/S8 contracts repeat the false "shadow unclipped" claim; A3, A4 and A1 are 0/6 as well.
- No Invalid findings in 16 Sonnet comments. NF4 remains the only Unconfirmed item, same as Opus.
