## Bugs no bot found

From commit messages and thread replies, defects or hazards the authors fixed that no bot raised:

1. **Hard-link move unsafe inside Google Drive (NIW2-577).** Commit `c36db614` ("feat(desktop): per-workspace cloud catalog and synced-folder safety (NIW2-602, NIW2-577)"), in `main/workspaces/move-item.ts`, `library/safe-place.ts`, `library/drag-copies.ts`, `recording/recording-writer.ts`. At the base (`543053c:move-item.ts:259-262, 286, 345-347`) part 2's mover used `fs.link(media, finalMedia)` whenever source and target were on the same device, with no regard for sync providers. Drive/OneDrive/iCloud treat a second name for a synced file as a rename or an unsync of the cloud item. The commit changes it so "nothing is hard-linked into or out of a synced workspace": `linkable = sameDevice && !synced`; a move with a synced side copies to a scratch staging folder, verifies sha256, places by rename (`placeByRename`), then re-hashes at the final path before deleting the source; drag copies are real copies; recorded takes stage in `userData/workspace-scratch/<id>/` and are placed by rename. No reviewer on #479 or #483 raised it; it is the stated reason for the PR's synced-folder half, found by the author.
2. **Change folder... ignored sync detection (`0253fd77`).** The merge commit message: "Change folder... now detects the new folder's sync provider and probes it with the bounded availability check, like every other path that registers or edits a workspace." The main-branch relocate handler (#478) had no provider detection; the author found the integration gap at merge. Wachiman's R5 then found the ordering problem (D16) in that same line, so the gap was visible to the reviewer only after the author closed it.
3. **Pre-emptive hardening bundled in `c36db614`, not raised by any bot:** `lastSeenLocalId` cache updates merged inside the catalog write chain (a cache race), the orphan heal skipping evicted items, the synced-workspace availability probe bounded and never listing the provider root. Wachiman's R1 batch 3 praised the write chain, so it was seen but not as a finding.
