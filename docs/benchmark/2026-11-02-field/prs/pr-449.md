## The CSS miss: every workspace tile grey, every tag chip rose

**Mechanism, confirmed at head `791af902`.**

- `features/library/tags/tag-palette.css` (new, 36 lines) holds ten rules of the form `[data-color="rose"] { --tag: #fb7185; }` and so on. Specificity (0,1,0).
- `features/library/tags/tag-chip.module.css:6-7` still has `.chip { --tag: #fb7185; ... }`, specificity (0,1,0). Before the PR the `[data-color]` block sat later in this same file, so it beat `.chip` on source order. The PR deleted that block (diff: `-40,37 +40,6`) and moved it to a separate file.
- `features/workspaces/workspace-switcher.module.css:15-16` (new file) has `.tile { --tag: var(--text-muted); ... }`, again (0,1,0).
- Import order puts the global palette before the module in both consumers: `tag-chip.tsx:4` imports `./tag-palette.css` and `:5` imports `./tag-chip.module.css`; `workspace-switcher.tsx:14` imports `tag-palette.css` and `:17` imports `./workspace-switcher.module.css`. Equal specificity plus later source order means the component default wins, so `data-color` never applies: tiles take `--text-muted` (grey), chips keep rose.
- Fix `7620879e` (merged in #478) confirms the cause in its message and moves the default into `var(--tag, ...)` fallbacks.

**Did Wachiman read those files?** Partly, and the miss is a reasoning gap, not a coverage gap.

- The review has no per-file list; the coverage table gives only file and line counts per batch. Batch 6 of 6 ("tests, stylesheets and messages", 12 files, 723 lines, highest risk 2, the lowest of the six) is where the stylesheets were reviewed: its summary says "**Stylesheets:** pulling the tag palette out into a global `tag-palette.css` is safe, because both `tag-chip.tsx` and `workspace-switcher.tsx` import it."
- So it read `tag-palette.css` and the two import lines. It checked that the palette reaches both consumers, which is true, and did not check what the consumers' own CSS does with `--tag`. That is the exact claim that turned out false ("safe").
- Whether it opened `tag-chip.module.css` and `workspace-switcher.module.css` is not recorded (inference: they are the only other CSS in the batch's theme, but I cannot prove it). Either way it did not notice the default.
- A correction to the field README, which says "the diff showed both files": the `.tile` default was in the diff (a new file, fully visible), but the `.chip` default was not. The `tag-chip.module.css` hunk covers only the deleted block (lines 40-76); the `.chip { --tag }` line at 7 was outside the diff context, so seeing it required opening the whole file, which a diff-driven review is unlikely to do for a pure deletion.
- Batch 6 also ranked as the least risky batch (2), so the CSS move got the least attention of the PR.

**Also noted:** the README line "The owner's manual test found no bug Wachiman had missed on this PR" contradicts its own item 1 under "Bugs no reviewer caught"; the grey tiles were found by looking at the app and fixed in `7620879e` (2026-11-01), after merge.
