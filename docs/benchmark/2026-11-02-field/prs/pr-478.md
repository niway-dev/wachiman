## Bugs no bot found

1. **The #449 CSS cascade bug (every workspace tile grey, every tag chip rose)**, fixed here in commit **`7620879e`** ("fix(desktop): workspace tiles and tag chips wear their palette color again"), at 03:46Z, after the first three bot rounds and not raised by any bot. Mechanism, from the diff: part 1 moved the palette into the global `tag-palette.css` (`[data-color="rose"] { --tag: … }`, specificity 0,1,0) and imported it before each CSS module. `tag-chip.module.css` `.chip { --tag: #fb7185 }` and `workspace-switcher.module.css` `.tile { --tag: var(--text-muted) }` also have specificity 0,1,0 and load later, so they won the cascade and every element kept its default instead of its `data-color`. Fix: delete the `--tag` declarations on `.chip` and `.tile` and use `var(--tag, <default>)` fallbacks at the readers (`.chip` border/background/colour, `.dot`, `.swatch`, `.tile`). Both Wachiman (Inc-3) and Pullfrog (4th review) then reviewed the fix and described the mechanism correctly, but neither saw the bug before the author fixed it (it is visible in the running UI, which is how it was likely found). I checked the remaining `var(--tag)` readers at 392778f: only `workspace-dialog.module.css:114` reads it with no fallback, on an element that always carries `data-color`.
2. **The dialog's fake input** (`33347387`): the folder was shown in an input-looking box that could not be selected or edited; replaced with plain read-only text plus Show in Finder / Change folder… buttons. A design/UX defect fixed inside a feature commit; no bot commented on the pre-fix look (it is not in the PR diff the bots saw, since the commit adds the relocate feature on top).
3. Nothing else the authors fixed was unreported: every other fix commit (`886d67f`, `649c902`, `8a8f83e`, `11317b1f`, `85200ab3`, `4a300696`, `64db30b`, `7e3555a`, `392778f`) answers a bot finding above.
