Wachiman — how one review run flows

JSON · engine only
Never reaches the model.
JSON · the model reads it
A side file the agent opens with its Read tool.
Markdown + XML · to the model
The prompt text itself.
JSON · from the model
Structured output via a JSON schema.
1
Triggers
when a run starts
GitHub Actions job: review
Reusable workflow review.yml. Fires on pull_request opened / ready_for_review / each push (push waits a debounce so a newer push cancels it unspent). Fork PRs and drafts never run. 30-min timeout.
→
GitHub Actions job: threads
Fires on a pull_request_review_comment reply written by the operator. Answers pending Wachiman threads only when the head was already reviewed.
→
GitHub Actions job: on-demand
Fires on an issue_comment by the operator containing /wachiman (or @agent-review, @claude). "review [paths]" runs the pipeline; anything else is one free-text answer call.
→
wachiman local (laptop)
Same core, run on a developer's clone with git only. Refuses to start if ANTHROPIC_API_KEY is set (uses the Claude subscription). Optional --history.
2
Connector
builds the input; code decides, no model yet
listFiles / git diff
GitHub connector reads the PR's changed files via gh; local-git connector runs one pinned git diff against the merge-base and splits it into GitHub's patch shape.
→
lastReviewedSha → compareFiles / rebaseDelta
Finds the engine's own signed marker in earlier reviews. If that commit is behind the head: review only what changed since. If the branch was rewritten: compare per file and review only the files that really changed.
→
resolveScope
"review src/a.ts docs/" words become paths; a word counts only as an exact changed file or a directory prefix.
→
readBaseInstructions
Fetches .github/wachiman.md, CLAUDE.md, AGENTS.md at the BASE commit (never the head), each cut at 64 KB. A PR cannot rewrite the rules it is reviewed under.
→
openThreads / ceilingRoom
Loads unresolved Wachiman threads where an OWNER/MEMBER/COLLABORATOR replied last. For automatic runs, sums the cost of earlier automatic runs from signed footers and caps this run at what is left of the per-PR ceiling.
→
ReviewInput (wachiman.review-input/1)
The contract between connectors and the core: change, files with patches, instructions, scope, since, conversation. It is never shown to the model.
JSON · engine only
3
Core · before the model
select, order, batch, assemble
filterFiles
Drops DEFAULT_EXCLUDE (lockfiles, build output, snapshots, source maps, generated) plus configured excludes. Binary / too-large files stay: the model must read them or record a closed skip reason.
→
riskScore
A weight from the PATH alone: 8 workflows, ipc/preload; 7 credential-like names, scripts/; 6 package.json, migrations, schema, infra/; 5 main/; else code 4, tests 2, docs 1. Orders work so a budget cut-off lands on the least risky files.
→
planBatches
Groups files by module so code, tests and docs of one module share a call; orders modules by riskiest file; packs into batches capped by changed lines and diff characters. An oversized file gets its own batch.
→
gatherEvidence → evidence.json
Extracts up to 12 call-like names from the batch's added lines, runs git grep -w -F for each in the head, keeps ≤6 call sites per name with 4 lines of context. File ≤16 KB; a ≤6 KB slice is inlined in the prompt inside <evidence>. 20-second wall clock; never fails the review.
JSON · the model reads it
→
selectQuestions
One regex trigger per data-path question (a delete that does not re-verify its target, a read error treated as empty and written back, two calls in flight on one store, an unbounded wait, a cached write over another writer). Matching questions are added to the prompt.
→
pr.json / threads.json
Written to a fresh mkdtemp run dir per batch call: PR title, body, author; the open threads for this batch's files with the code around each finding. Removed after the call.
JSON · the model reads it
→
buildBatchPrompt + annotateDiff
In order: what is reviewed and the head sha; orientation list of every selected file; this batch's files; the line-number rule; evidence slice; thread instruction; FLOW_QUESTIONS; data-path questions; RULES (severity tests, topics, evidence rules, confidence); <instruction-file> blocks from the base commit; finally <diff> with every line prefixed by its line number at the head. Sent through stdin.
Markdown + XML · to the model
4
The model
the only part that judges
Provider adapter (claude -p or codex)
Claude Code: --restricted, --strict-mcp-config, --tools Read,Glob,Grep, --max-budget-usd (soft cap), allowlisted env (no GH_TOKEN). Codex: read-only sandbox, no dollar cap, 15-min SIGKILL. The agent starts in an EMPTY scratch dir with the head as a readable extra dir, so the head's CLAUDE.md and hooks never auto-load.
→
The agent reads
Opens files in full with Read/Glob/Grep, follows callers, opens pr.json, threads.json, evidence.json. The engine cannot observe what it read.
→
Structured output (SCHEMA)
files_reviewed, files_skipped (closed reasons only: binary, no_diff_and_unreadable), findings (path, line, severity, topic, title, body, confidence), contracts (with cites), thread_replies, summary. Plus cost, turns, duration and a stop reason: success / budget / turns / timeout / error.
JSON · from the model
5
Core · after the model
verify what code can verify
relativisePaths / checkOutput
Strips the absolute head path. Drops a confidence not in high/medium/low. Each contract cite must point to a file and line that exist in the head; otherwise evidence_checked: false and a warning.
→
batchGaps → one retry
Files of the batch the model did not list in files_reviewed (a skip counts only with a closed reason and only for a file with no patch). If gaps and ≥ $0.05 left: rerun the batch with only those files. Still missing → the review is "Partial" and names them.
→
Budget arithmetic
spent accumulates first calls and retries. Each call capped at min(per-batch cap, remaining). A batch is not started under $0.05: its files are "not reached". A call that died with no result counts at its full cap. Budget is per run, not per PR.
→
mergeOutputs
dedupeFindings: one per path+line+topic, higher severity wins. mergeContracts: one per action+location, resolved-cites beats unresolved beats open. A file reviewed in the retry counts as reviewed.
→
enforceConfidenceRule / adrNotices / anchor
A low-confidence Blocker or Fix is rewritten to the question topic. One Info·adr finding per reviewed docs/adr/ file. commentableLines decides whether a finding can sit inline on the diff.
→
ReviewResult (wachiman.review-result/1)
coverage, findings with anchors, contracts, summary, per-batch reports, thread replies, execution (cost estimate, calls, stop reason).
JSON · engine only
6
Sinks
render and post; the model never touches GitHub
buildReview
Labels each finding (emoji + severity + topic); inline comments for findings on added/context lines; "Outside the diff" for the rest; every Info under "For your information". First line says complete or partial; then summary, collapsed "What the change connects to" (contracts), coverage-by-batch table, footer with model, batches and cost. Body kept under MAX_BODY_CHARS.
→
neutralise + signatures
Every piece of model text and every repo-controlled string has <!-- and --> escaped, so neither can forge a marker. The engine then adds its own <!-- wachi:review -->, <!-- wachi:finding -->, <!-- wachi:reply --> and, only for a complete unscoped review, the incremental marker <!-- agent-review sha=… -->.
→
refuseLeak → postReview (COMMENT)
Aborts the whole post if any text looks like a provider key. Posts one review with event COMMENT: never approve, never request changes. Transient 422 retried after 1 s and 3 s with an attempt id so a landed POST is not duplicated. A validation 422 moves inline comments into the body.
→
Thread reply POSTs
Only for comment ids the engine itself handed to the model; one POST each, after the review.
→
Local sinks + history
terminal, Markdown or JSON rendering of the same ReviewResult. With --history: reconcile against the repo's earlier runs under ~/.wachiman/history (never leaves the machine) and annotate new / persisting / gone findings.

Key facts

  • Thesis: the model only judges. Everything code can decide (which files, in what order, how many per call, whether every file was accounted for, what gets posted) is decided by code before and after the call.
  • The prompt the model reads is Markdown with XML tags and a line-numbered diff. The JSON formats review-input/1 and review-result/1 are contracts between engine parts and never reach the model.
  • The only JSON the model reads are three small side files per batch: pr.json, threads.json, evidence.json (≤16 KB).
  • The model's answer is JSON constrained by a schema; that is what makes the coverage check and the cite verification deterministic.
  • "Reviewed" always means "reported as reviewed by the model": the engine cannot see what the agent actually read; it only checks the agent's own list against the selected files.
